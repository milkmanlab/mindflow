# プロダクト要求定義書

> 本書は既存実装（v0.1.0）から起こしたものです。「（要確認）」の付いた項目は、まだ値が決まっていません。

## 1. プロダクトビジョンと目的

**ビジョン**
Markdown で書いた思考を、そのままマインドマップとして眺め、キーボードだけで素早く組み立て直せるようにする。

**目的**
- 普段使っている VS Code と `.md` ファイルの中で、マインドマップによる思考整理を完結させる
- マインドマップのデータを独自形式に閉じ込めず、プレーンな Markdown として残す。これにより、Git での差分管理、GitHub 上での閲覧、テキストエディタでの直接編集ができる
- 外部サーバーやネットワーク通信なしで、ローカルだけで動作させる

## 2. ターゲットユーザーと課題・ニーズ

**ターゲットユーザー**
- VS Code を日常的に使い、メモやドキュメントを Markdown で管理しているエンジニア・ライター
- 設計・企画・学習メモなどの思考を、ツリー構造で整理したい人

**課題**
- 既存のマインドマップツールは独自形式やクラウド保存が多く、Git 管理やテキストでの編集がしにくい
- Markdown の箇条書きだけでは、全体の構造や枝同士の関係が見えにくい
- マウス操作中心のツールでは、思考の速度に入力が追いつかない

**ニーズ**
- `.md` ファイルを開くだけでマインドマップになり、編集結果がそのまま `.md` に戻る
- キーボードだけでノードの追加・移動・編集ができる
- 色・アイコン・画像・関連線などで、テキストだけでは表しにくい情報を補える

## 3. 主要な機能一覧

| 分類 | 機能 |
|---|---|
| 同期・保存 | `.md` / `.markdown` との双方向同期、自動保存、VS Code の未保存表示との連携 |
| ノード編集 | 子・兄弟ノードの追加、インライン編集（複数行可）、削除、コピー＆ペースト |
| 構造操作 | 兄弟の並べ替え、ドラッグ＆ドロップでの親の付け替え、折りたたみ・展開 |
| 選択 | 単一選択、Shift/Ctrl/Cmd クリックでの追加選択、Shift ドラッグでの範囲選択、一括変更・一括削除 |
| ノード装飾 | 色、文字色、アイコン、進捗（0/25/50/75/100%）、形状、フォントサイズ、太字・斜体・下線、メモ、リンク、画像 |
| 関連線 | 枝をまたいだノード同士を矢印で結ぶ。ラベル、色、線種、矢印の向きを設定できる |
| 表示 | レイアウト（マインドマップ、右ツリー、左ツリー）、接続線スタイル、テーマ 4 種、フォント 3 種、ミニマップ、ズーム・パン、全体表示 |
| ナビゲーション | 矢印キーでの移動、ルート・末端へのジャンプ、マップ内のテキスト検索 |
| エクスポート | PNG、SVG |
| その他 | ショートカット一覧（`?`）、ブラウザ単体での動作（開発・プレビュー用） |

## 4. 成功の定義

- マウスに持ち替えずに、新しい思考ツリーを作り切れる
- マインドマップで編集した `.md` を Git で管理したとき、差分が読める形で出る
- テキストエディタで `.md` を書き換えても、マインドマップのデータが壊れない
- 数百ノード規模のマップでも、操作に引っかかりを感じない

## 5. ビジネス要件

- VS Code 拡張機能（`.vsix`）として配布する。発行者は `milkmanlab`
- 対応バージョンは VS Code 1.80 以降
- マーケットプレイスでの公開方針、ライセンス、収益化の有無（未定）

## 6. ユーザーストーリー

| ID | ストーリー |
|---|---|
| US-01 | ユーザーとして、既存の `.md` ファイルをマインドマップとして開きたい。手元の文書の構造をすぐに見渡せるようにするため |
| US-02 | ユーザーとして、`Tab` と `Enter` だけで子・兄弟ノードを作りたい。思いついた順に手を止めずに書き出すため |
| US-03 | ユーザーとして、マインドマップでの編集を自動で `.md` に保存してほしい。保存し忘れを防ぐため |
| US-04 | ユーザーとして、テキストエディタで `.md` を直接書き換えても、マインドマップに反映してほしい。慣れた方法でも編集するため |
| US-05 | ユーザーとして、ノードをドラッグやキー操作で並べ替え・付け替えしたい。考えがまとまるにつれて構造を組み直すため |
| US-06 | ユーザーとして、ノードに色・アイコン・進捗・画像を付けたい。重要度や状態を一目でわかるようにするため |
| US-07 | ユーザーとして、離れた枝のノード同士を関連線で結びたい。因果関係や依存関係を表すため |
| US-08 | ユーザーとして、複数のノードをまとめて選択し、一括で装飾・削除したい。同じ操作を繰り返さないため |
| US-09 | ユーザーとして、マップを PNG や SVG で書き出したい。資料に貼ったり共有したりするため |
| US-10 | ユーザーとして、大きなマップの中からテキスト検索でノードを探したい。目的の場所にすぐ移動するため |
| US-11 | ユーザーとして、コマンド 1 つで（名前を考えずに）新しいマインドマップを作り、あとからクリックするだけで同じマインドマップとして開きたい。普通の `.md` は今まで通り開いてほしい |

## 7. 受け入れ条件

- **US-01**：`.md` を右クリックして「プログラムから開く」→「MindFlow マインドマップエディタ」を選ぶか、コマンド `MindFlow: マインドマップとして開く` を実行すると、マインドマップが表示される
- **US-02**：`Tab` で子ノード、`Enter` で下の兄弟ノード、`Shift + Enter` で上の兄弟ノードが追加され、そのまま入力状態になる
- **US-03**：編集すると自動で `.md` に書き込まれ、保存状態がツールバーに表示される
- **US-04**：テキストエディタで `.md` を変更すると、マインドマップが再描画される。自分の保存が戻ってきたことによる再描画のループは起きない
- **US-05**：`Alt + ↑ / ↓` で兄弟の順序が入れ替わる。ドラッグ＆ドロップで、ノードの上下に落とすと並べ替え、中央に落とすと子ノードとして移動する。放射状のマップでは、ルートの左半分・右半分に落とすと、その側の枝に移る
- **US-06**：設定した属性は `.md` に保存され、開き直しても元に戻る
- **US-07**：関連線は `.md` 内の `<!-- mindflow-relations:[...] -->` に保存される。結んでいたノードを削除すると、その関連線も消える
- **US-08**：複数選択した状態で `Delete` を押すと、選んだノードが子孫ごと削除される。ルートノードは削除されない
- **US-09**：ツールバーから PNG または SVG を保存できる。VS Code 上では保存先を選べる
- **US-10**：`Ctrl/Cmd + F` で検索バーが開き、一致したノードに移動できる
- **US-11**：コマンド `MindFlow: 新規マインドマップを作成`（コマンドパレット、またはエクスプローラーでフォルダを右クリック）を実行すると、`Untitled-1.mindflow.md` のように（画面の言語によらず `Untitled` 固定）、空いている最小の番号の名前で作られ、すぐマインドマップで開く。名前の入力は求めず、変えたいときはエクスプローラーで改名する。既存のファイルは上書きしない。`*.mindflow.md` はクリックするとマインドマップで開き、普通の `.md` は今まで通りテキストエディタで開く（中身はどちらも通常の Markdown）

## 8. 機能要件

### 8.1 Markdown との同期
- YAML フロントマターにマップ設定（タイトル、レイアウト、テーマ、接続線スタイル、フォント、更新日時）を保存する
- `# 見出し` をルートノード、2 スペースずつインデントした `- ` 箇条書きを子ノードとして扱う
- 進捗は `- [x]` / `- [ ] テキスト (50%)` のタスク記法で表す
- その他のノード属性は HTML コメントに JSON で保存する。通常の Markdown プレビューや GitHub ではコメントが表示されないため、普通の箇条書きとして読める
- Markdown → マップ → Markdown の往復変換で、データが失われない

### 8.2 編集・操作
- ノードの追加・編集・削除・コピー・ペースト・並べ替え・親の付け替え・折りたたみ
- 選択ノードの上で文字キーを押すと、そのまま編集を始められる。上書きか追記かは設定で切り替えられる
- 編集中は `Alt + Enter` / `Ctrl + Enter` で改行できる
- `Ctrl/Cmd + Z / Y` で Undo/Redo できる（100 回まで）。履歴は開いている間だけ持ち、テキストエディタでの編集など外部の変更があると作り直される

### 8.3 画像
- クリップボードからの貼り付け、ファイル選択、URL 指定、ドラッグ＆ドロップで画像を添付できる
- 画像は URL または Base64 の Data URL として `.md` に保存する
- 画像は切り抜かずに全体を出す。ノードを選ぶと角につまみが出て、ドラッグで表示の幅を変えられる（幅と縦横比は、ノードの属性として `.md` に保存する）。画面いっぱいの拡大表示はない

### 8.4 表示・エクスポート
- レイアウト、接続線スタイル、テーマ、フォントを切り替えられる
- ズーム・パン・全体表示・倍率リセット・ミニマップを提供する
- PNG / SVG でエクスポートできる。画像を添付したノードも含めて出力する

## 9. 非機能要件

| 分類 | 要件 |
|---|---|
| 動作環境 | VS Code 1.80 以降。ブラウザ単体でも動作する（localStorage に保存） |
| オフライン | 外部サーバーやネットワーク通信を必要としない |
| データ互換性 | 保存形式は標準的な Markdown。手で編集しても壊れにくい |
| 性能 | 画像を含むマップでも、ドラッグ・ズーム・パンが快適に動く。数百ノード規模で操作に遅延を感じない（目標値は要確認） |
| 品質 | CI で型チェック・テスト・ビルドがすべて通る |
| セキュリティ | 外部リンクは VS Code 経由で開く。ノードのテキストや画像 URL を表示するときは XSS に注意する |
| UI 言語 | 日本語 |

| 項目 | 内容 | 判断のポイント |
|---|---|---|
| 専用ファイル形式 | `.md` ではなく、`.mf` などの専用拡張子で保存するか | 現在の目的（Git での差分管理、GitHub での閲覧、テキストエディタでの直接編集）と、ビジョンに関わる。専用形式にすると、通常の `.md` を開いたときにこの拡張機能が候補に出なくなる一方で、Markdown 記法の制約を受けずに属性を保存できる。なお、中身は `.md` のまま、名前だけ `*.mindflow.md` にして「クリックで開く」を実現する方式は 1.0.0 で採用済み（US-11） |
